## Frozen question and selection rule

Can a source actually accessible to this unprivileged process on this Mac bind
one artificial file operation to its actual causing process instance, without
self-report, test-control knowledge or mere timing correlation?

Select only a live kernel-origin action record containing the actual actor and
file identity, with defensible same-instance start/lifecycle binding. PID/start
snapshots, open FD ownership, Mach message senders, file timestamps and process
I/O counters alone do not qualify. A write notification is not proof of durable
bytes. Logical agent/model/person/conversation identities remain UNBEKANNT.

First compile a small SDK-based availability probe, not an attribution engine.
It refuses effective UID0. Query only its own BSD process start, its own Mach
TASK_AUDIT_TOKEN and one read-only FD for an empty artificial file. Query audit
condition with A_GETCOND and attempt read-only nonblocking auditpipe access;
do not consume audit records or alter audit configuration. One es_new_client
attempt at nonroot/no ES entitlement checks rejection: never subscribe, reply
AUTH, change mute/cache settings or request TCC. Unexpected success stops the
round; release the client only. No privilege grants/signing entitlements.
Check fs_usage's nonroot rejection with a one-second/self-PID bound; DTrace
only lists the write provider, never enables it. Commands have hard timeouts.
FSEvents/kqueue contracts are read only; no repeat of the old ineffective
attribution approaches. Existing Mach handshake is not repeated.

No sudo, auditctl/A_SET*, audit daemon starts, task_for_pid/ptrace/target
instrumentation, SIP/TCC changes, remote/system logs, production file writes,
all-process FD scans or model calls. All probe output outside the repository
in a fresh temporary directory; only minimized diagnostic records archived.

## Conditional experiment (only after a qualifying source)

Exactly six artificial cases: A writes target; B idle; C writes another file;
child writes target; false claimed PID; two processes sequentially write target.
Fresh files/held file identities, frozen boundaries and separate oracle log not
passed to observer. Record event actor PID/lifecycle/start, dev/inode/generation,
clock/version/dropped-record indicators, observed write versus final-state check.
Use minimal NOTIFY data only; no operational intervention. If source, instance
binding, temporal precision or coverage is missing, affected attribution is
UNBEKANNT. If no channel qualifies, all six cases are explicitly NOT EXECUTED,
not six failed writes and not a positive/negative attribution battery.
